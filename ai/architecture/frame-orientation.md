# Frame orientation

FrameImageConverter produces a single upright bitmap for detection, quality checks, enrollment and recognition. Detected FaceBox pixels, normalized observation bounds and the encoded analysis JPEG all refer to that bitmap. The preview overlay maps normalized upright bounds into the AspectFill view; it must not rotate or mirror them again.

CameraFrame.Rotation specifies the clockwise rotation from sensor space into upright space. IsMirrored requests a horizontal mirror of that upright image. In the Skia matrix, the canvas is centered on the destination, Scale(-1, 1) is concatenated before RotateDegrees, and the origin is moved to the source center. Matrix composition then rotates source pixels first and mirrors the upright result. Mirroring in sensor space instead produces a 180-degree discrepancy for mirrored 90/270-degree frames.

The shared operation is implemented in [FrameImageConverter](../../src/Shiny.FaceIntelligence.Maui/Internals/FrameImageConverter.cs). Android YUV, Apple BGRA and Windows bitmap conversion use it. [FrameImageConverterTests](../../tests/Shiny.FaceIntelligence.Tests/FrameImageConverterTests.cs) compare every pixel of an asymmetric labeled bitmap for all eight quarter-turn/mirror combinations, in addition to the upright width-cap tests. These tests exercise the production bitmap operation without a native camera and do not establish native preview behavior or recognition accuracy.

Changing this convention affects stored analysis images and may affect embeddings generated by earlier package versions. Detector and comparison still share the exact same converted JPEG within one frame. Recognition thresholds are independent and are not changed to compensate for coordinate errors. Existing stored media are not rewritten and local enrollment is not automatically deleted.

## Known issues

- Front-camera preview agreement still requires native device verification, including actual frame rotation/mirror metadata and left/right/up/down movement. Synthetic bitmap tests cannot prove CameraX/AVFoundation preview cropping or timing.
- Existing templates captured with the former sensor-space mirror may not be compatible with newly oriented probes. Old-versus-new enrollment must be evaluated before rollout; an explicit version-bound re-enrollment policy may be needed. No automatic migration or deletion is implemented.
